# Scoped review protocol

At the frozen base/head revision, export the complete diff to a private file. Give each reviewer the same neutral requirements, repository instructions, literal SHAs, and complete diff path. Do not include implementation dialogue or the orchestrator's preferred verdict.

Launch three fresh, separate Codex sessions in read-only sandbox mode, one for each of `review-correctness.md`, `review-compliance.md`, and `review-completeness.md`. Use Ralph's `reviewer` command with the absolute executable path supplied in the orchestrator prompt: `node /absolute/path/to/ralph/dist/cli.js reviewer --cwd <repo> --prompt <private-prompt-file> --output <new-output-directory> --head <literal-head-sha>`. Create a private `review-sessions/` parent directory first. Use exactly `review-sessions/correctness`, `review-sessions/compliance`, and `review-sessions/completeness` for the initial calls. The command verifies the local head and saves JSONL, stderr, the last response, and a success/session receipt; Ralph requires all three receipts before a code-change run can complete. After a repair, use a new `review-sessions/correctness-2` (then `-3`) directory for the final head. Confirm the reviewed head SHA in each report. A resumed implementation session is not independent review. Run no other lenses unless the user's task requires them.

Each finding must identify a reachable input or sequence, expected versus actual behavior, the changed source location, and evidence. A finding without a concrete consequence is a suggestion. Combine duplicate findings and check every claim against the current source. For a potentially blocking finding, investigate the strongest plausible counterargument before deciding. Record VALID, PARTIALLY VALID, or FALSE POSITIVE with the observed trigger and impact. Send the original finding text and neutral acceptance contract to Claude for skeptical adjudication; independently verify its response. Neither model's confidence alone clears a blocker.

After accepted fixes, freeze a new head and rerun correctness only. Reopen compliance or completeness only if the edit invalidates their previous evidence. The initial pass and at most two repair/review cycles share one budget. Save each report and verification ledger in the run directory, retaining earlier versions rather than overwriting the basis of a prior decision.
